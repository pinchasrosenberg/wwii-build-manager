## Initial findings and requested bounded fixes

| Priority | Initial draft behavior | Small correction |
|---|---|---|
| P1 — temporal meaning | `TimeScope` accepts `1944-02-31`, `not-a-date`, and `INTERVAL` with no end. Lexical comparison rejects the chronologically valid interval `1944-08-26T13:00:00+02:00` → `1944-08-26T12:30:00Z`. | Parse calendar values under precision-specific formats; require interval bounds; compare parsed values, normalizing offsets only when known. Reject unsupported mixed precision/aware-naive comparisons or represent them as explicitly indeterminate. Preserve unknown source time zones and coarse source precision; never fill a missing clock to make comparison convenient. |
| P1 — accepted price mutability | A frozen `Quote` still permits `quote.price.minor_units = 900` after creation at 100, because nested `Money` is mutable. | Freeze `Money` or store an immutable price snapshot. Quote/acceptance must bind canonical serialized content and its digest, not trust object identity. Immutability of a Python object is only one part of the persisted quote guarantee. |
| P1 — completion semantics | `CapabilityResult(status='SUCCEEDED')` accepts a blocking gap; `PARTIAL` accepts an empty gap list. | Reject success with blocking gaps; require a declared unresolved gap for partial results. Optional nonblocking gaps may accompany success if policy permits. The resolver must additionally verify that required output schemas/artifacts and acceptance criteria are met. A gap list alone does not prove successful completion. |
| P1 — unsupported certainty | `HistoricalClaim` accepts a non-null value of 10,000 with `basis='UNKNOWN'`; a disputed claim needs no opposing claim or conflict explanation. An unbacked HARD envelope accepts an invented preferred instant even when its time is UNKNOWN. | Require unknown claim values to be null; require disputed claims to reference competing claims or an explicit unresolved-conflict record. HARD historical anchors/envelopes need claim/evidence references. Make preferred scheduling instants explicitly reconstructed unless separately documented, bound them to the allowed envelope, and disallow exact hints when no usable temporal bounds exist. |
| P1 — person knowledge boundary | `ContextGrant(knowledge_scope='PERSON_KNOWN_AT_TIME')` accepts no person, no time and expiry `whenever`. | Require a person identity and a usable knowledge cutoff for this scope. Parse request deadlines, grant expirations and quote expirations as engineering instants with explicit time zones; these are different from uncertain historical dates. Actual knowledge filtering still needs semantic enforcement and delivery-time checks. |
| P1 — validation claims | The schema bundle contains only `$defs`, so validating a document against the bundle root alone checks no payload type. Pydantic `model_validator` rules do not appear automatically in the generated JSON Schema. | Document validation through a named `$defs` entrypoint. State precisely that JSON Schema validates expressible wire structure and Pydantic/semantic validators enforce additional invariants. Encode convenient conditional constraints in JSON Schema if desired, but do not imply feature parity without a conformance check. |

The temporal fix should include at least one invalid date, one coarse date without an invented timestamp, a reversed interval, an interval with offsets whose lexical order differs from time order, an unknown source zone, and a missing interval endpoint. These are meaningful contract checks, not requests for a broad historical test corpus.

## Keep these as explicit semantic validation gates

The draft need not implement these systems now. Its schema/architecture documentation should identify them as additional validation, and avoid describing string references or nonempty lists as proof:

- A source hash, locator and review reference must resolve to the exact source bytes, region/passage and review scope. A nonempty `review_refs` list does not establish reviewer independence. Legacy `AtlasFact`/`safe_for_factual_answer` imports require the separately documented trust gate.
- `AccuracyManifest` must cover release-critical entity fields without duplicate or contradictory entries. Documented weather fields need resolved claim support, unknown weather values need explicit absence, and historical terrain needs dated admission rather than a modern layer renamed HISTORICAL.
- Episode time/place, terrain/weather applicability, equipment production versus date/unit/theater availability, strengths, participants and anchors must be compatible. Equal variant ID strings are useful but do not establish that mesh and physical component artifacts actually represent that variant/configuration revision.
- HARD constraints need reviewed admissible evidence and a feasible causal domain. Soft preferences and illustrative scheduler choices cannot become historical fact. Player divergence uses the explicit conflict policy; sources cannot be rewritten to make a session fit.
- Draft `EpisodeSpec` may validly lack completed reviews. A **release** needs resolved HistoricalValidation, ProvenanceValidation, SimulationValidation, IntegrationValidation and ExperienceReview receipts. Keep the construction schema distinct from a release certificate; do not invent positive review results to satisfy required fields.
- Quote acceptance checks bound request/scope/version, expiry, currency, authorization and reservation atomically. Execution, settlement and cancellation need idempotent journals and reconciliation; the current schemas do not implement those guarantees. Known actual cost requires a resolving receipt under settlement policy, while unavailable cost remains null.
- Numeric quality values require a named rubric, evaluator and scope. Historical fidelity scores guide investment only after hard historical gates; they do not numerically promote epistemic status or average away a disputed identity.

## Experience and future VR

The experience document now targets an embodied unit role, companions, quiet activities, persistent consequences and independent playtesting. This meets the new product direction at architecture level. Its concrete 20-minute loop is a proposed runtime design, not a documented chronology. The exact unit, role, weapon, vehicle and historical action remain evidence-gated.

The updated architecture selects Godot/OpenXR with an initially typed Godot domain module and an M1 device/experience spike; Rust is a possible later component, not a required initial layer. This is a provisional design, with no engine/game/VR execution verified by this review. Keep embodiment, camera, locomotion comfort, input and accessibility policies in `ExperienceSpec`/presentation profiles or referenced interface contracts. Future VR must consume the same historical identities, setting, events, world/simulation state and evidence revision. It cannot acquire its own “VR history” or alter anchor semantics to compensate for presentation. VR comfort/locomotion needs ExperienceReview and physical-world consistency checks; none of that requires a separate historical truth schema.

The Deliver port correctly stays outside the fixed physics tick, and the documented replacement gate explicitly calls real interoperability unverified. Retain that limitation until a real adapter and conformance run exist. The local simulator must use synthetic credits and local fixtures; a successful synthetic quote exercise is not evidence of production settlement correctness.
